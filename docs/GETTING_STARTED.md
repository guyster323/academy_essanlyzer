# 초보자 가이드 — ESS BMS 이슈 분석 워크스테이션

이 문서는 코드를 몰라도 따라 할 수 있도록 처음부터 끝까지 설명합니다. 터미널을 한 번도 안
써봤어도 괜찮습니다.

## 이게 뭔가요?

배터리(ESS) 로그 파일을 올리면, AI가 이상한 구간을 찾아주고 원인 후보를 몇 가지 제안해주는
도구입니다. 다만 **AI가 최종 결론을 내리지는 않습니다** — 어떤 원인이 맞는지, 얼마나 심각한지는
항상 사람(엔지니어)이 마지막에 확인하고 고릅니다. 근거가 서로 어긋나면 앱이 한쪽을 고르지
않습니다. 판단할 근거를 빠짐없이 보여주는 것이 이 도구의 역할입니다.

로그 파일은 여러분 컴퓨터(브라우저) 밖으로 나가지 않습니다. 서버로는 통계 요약과 몇 줄의 샘플만
전달되고, 원본 파일 전체는 절대 전송되지 않습니다.

## 1단계 — 필요한 것 설치하기

### (1) Node.js 설치

- [nodejs.org](https://nodejs.org)에서 **LTS 버전**을 내려받아 설치하세요.
- 설치 후 터미널(Mac: 터미널 앱, Windows: PowerShell)에서 아래 명령이 버전 번호를 출력하면
  성공입니다.

  ```bash
  node --version
  ```

### (2) Claude Code CLI 설치 + 로그인

이 도구는 이미 여러분이 쓰고 있는 Claude 구독(Pro/Max/Team)을 그대로 재사용합니다 — 별도
API 키나 추가 비용이 들지 않습니다.

- macOS/Linux: `curl -fsSL https://claude.ai/install.sh | bash`
- Windows(PowerShell): `irm https://claude.ai/install.ps1 | iex`

설치 후 터미널에서 `claude` 라고만 입력해서 로그인 안내가 뜨면 화면 지시대로 로그인하세요.

## 2단계 — 프로젝트 내려받고 실행하기

```bash
git clone <이 저장소 주소>
cd ESSAnlyzer
npm install
cp .env.example .env
npm run dev
```

터미널에 `http://localhost:5173` 같은 주소가 뜨면, 그 주소를 브라우저(크롬 등)에 붙여넣어
열어보세요. 아래와 같은 화면이 보이면 성공입니다.

> 💡 처음 실행할 때 `npm install`이 몇 분 걸릴 수 있습니다. 인터넷 연결만 확인하고 기다려 주세요.

## 3단계 — 첫 분석 해보기 (샘플 약 15분, 대용량 로그는 30–36분)

화면 위쪽에 "샘플 케이스 불러오기" 버튼이 있습니다. 이 버튼을 누르면 예시 데이터가 자동으로
채워지므로, 여러분의 진짜 로그 파일이 없어도 전체 흐름을 바로 체험할 수 있습니다.

1. **"샘플 케이스 불러오기"** 클릭 → CS 의뢰 내용 예시 텍스트가 채워집니다.
2. 아래 체크박스("고객명·사이트 위치... 제거했음을 확인합니다")를 체크합니다.
3. **"이상 구간 탐지 시작 →"** 클릭 — 여기서부터는 AI가 응답을 만드는 동안 기다려야
   합니다. 내장 샘플은 단계마다 약 3–6분, 세 단계 합계 873.6초(약 14.6분)입니다. 실제
   대용량 로그는 이상 구간 탐지만 12–19분, 전 과정 약 30–36분입니다. 화면에 경과 시간이
   계속 올라가면 멈춘 게 아니라 생각 중입니다(출력 토큰의 87–94%가 extended thinking).
   타임아웃 기본값은 30분입니다.
4. 결과가 나오면 **"원인 가설 생성 →"**을 눌러 다음 단계로 진행합니다.
5. AI가 제안한 가설 중 하나를 클릭해서 선택하고, 심각도(상/중/하)를 직접 고른 뒤 사유를
   한 줄 적습니다. **이 단계는 반드시 사람이 직접 해야 하며, 건너뛸 수 없습니다.**
6. **"보고서 초안 생성"**을 누르면 보고서와 CS 회신 메일 초안이 만들어집니다. 필요하면
   직접 수정한 뒤 복사해서 사용하면 됩니다.

## 4단계 — 진짜 로그 파일로 분석하기

준비한 CSV/TXT/LOG 파일이나 ZIP 아카이브가 있다면:

1. **"CSV/TXT/LOG 파일 추가"** 또는 **"ZIP 아카이브 업로드"**로 파일을 올립니다.
2. 대용량 파일(수백 MB 이상)은 목록에만 먼저 표시됩니다 — **"분석 포함(스트리밍 시작)"**을
   눌러야 실제로 읽기 시작합니다. (불필요하게 시간을 오래 쓰는 걸 막기 위한 안전장치입니다.)
3. 파일이 처리되면 이상 징후 후보가 자동으로 나타납니다. 클릭하면 CS 의뢰 내용이 채워집니다.
4. 이후 흐름은 3단계와 동일합니다.

> ⚠️ **실제 고객 데이터를 사용할 때는 반드시 고객명·사이트명·담당자 등 개인정보를 지운
> 뒤에 업로드하세요.** 화면의 체크박스와 자동 검사가 이를 도와주지만, 최종 책임은 사용자에게
> 있습니다.

## 자주 묻는 질문

**Q. "claude: command not found" 같은 오류가 떠요.**
A. Claude Code CLI가 설치되지 않았거나, 터미널을 새로 열지 않아서 PATH가 반영되지 않은
경우입니다. 터미널을 완전히 껐다가 다시 켜보세요.

**Q. AI 응답이 너무 오래 걸려요(2~3분 이상).**
A. 정상입니다. 내장 샘플도 단계당 214–341초(합계 약 15분)이고, 대용량 LFP 로그는 이상 구간
탐지 12–19분·가설 약 9분·보고서 약 8분이 실측됐습니다. 화면의 경과 시간이 계속 올라가고
있다면 멈춘 게 아니라 extended thinking 중입니다. 타임아웃 기본값은 30분입니다.

**Q. 업로드한 ZIP 안의 일부 파일이 "읽기 실패"로 표시돼요.**
A. 해당 파일 하나만 문제가 있는 것이며, 나머지 파일은 정상적으로 계속 처리됩니다. 원본이
정말 손상되었을 수도 있으니 다른 방법으로 압축을 풀어 파일이 정상인지 확인해보세요.

**Q. 결과를 다른 사람에게 공유하려면 어떻게 하나요?**
A. 케이스 기록은 브라우저 세션에만 저장되고 새로고침하면 사라집니다. 보고서/메일 초안은
화면의 복사 버튼으로 복사해서 사내 문서·메일에 붙여 넣어 사용하세요.
