# Large ZIP Entry Fallback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stream `field_data/data_sys_6.csv` and other ZIP entries whose JSZip uncompressed size is signed-wrapped by reading only the entry's compressed byte range from the browser `File` and inflating it with an explicit streaming dependency.

**Architecture:** Keep JSZip for archive cataloging and ordinary entries. Preserve the original archive `File` in every ZIP-entry ref, and add a focused ZIP fallback stream that locates the entry in the central directory, parses its local file header, reads compressed bytes with bounded `File.slice()` chunks, and pushes deflate data through pako into `Uint8Array` output chunks. The normal `internalStream()` path remains the default for healthy entries; signed-size entries use the direct path before streaming, while an unexpected JSZip size-mismatch error causes a fresh direct retry so already-consumed chunks are never duplicated.

**Tech Stack:** Vanilla JavaScript, Node.js built-in test runner, Vite, JSZip 3.10.1, explicit pako 1.0.11.

**Spec:** `tmp/CODEX_TASK_ZIP_FIX.md`

## Global Constraints

- Keep raw log bytes client-side; modify only `src/` for runtime behavior and do not touch `server/`.
- Do not add `Log_sample/` archives or binary fixtures to git; use a small synthetic ZIP for automated regression coverage.
- Preserve the `Uint8Array` async-iterable contract consumed by `streamIntoSource()`; do not add a special case above the streaming layer.
- Never materialize the full archive, compressed entry, or decompressed entry; only bounded header/central-directory ranges and stream chunks may be held.
- Keep `markSourceError()` and `formatZipEntryError()` as the final error path when direct fallback fails, so the source remains isolated and sibling entries continue.
- Probe prefixes must use the same fallback-aware byte source and must not assume the full stream is the only affected path.
- Run `npm run test:unit`, `npm run build`, and the real-file manual verifier when the archive is available; record observed results honestly in `DONE.md`.
- Work only in this linked worktree, make one local commit after verification, and do not push.

- [x] **Step 2: Implement bounded archive range reads and ZIP metadata parsing**

In `src/zip-stream.js`, read at most the ZIP tail needed to find EOCD, then only the central-directory byte range. Match the target `entry.name`, parse method, flags, compressed size, uncompressed size, local-header offset, and ZIP64 extra values when present and safe. Read exactly the 30-byte local header plus filename/extra lengths, validate signature `0x04034b50`, and derive the compressed data offset without reading the entry body into one buffer.

- [x] **Step 3: Implement store/deflate output as bounded async chunks**

For method `0`, yield bounded slices directly. For method `8`, instantiate `new pako.Inflate({ raw: true, chunkSize: 64 * 1024 })`, feed bounded compressed slices with `push(chunk, false)`, drain `onData` output immediately, finish with `push(new Uint8Array(0), true)` when needed, and throw pako's error message when inflation fails. Keep the current pause/resume JSZip iterator for normal entries. When an archive blob is present and `entry._data.uncompressedSize < 0`, select the direct generator before any JSZip output is consumed. Make the mismatch predicate match only `/uncompressed data size mismatch/i` so unrelated corruption still follows the ordinary error path.
